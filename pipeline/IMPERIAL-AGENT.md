# Imperial Agent expansion

Operative and Sniper retain the existing equipment, artifacts, run upgrades, replacement rules and six offensive/three utility slots, plus a free replaceable primary starter. No relics or raid loot were added. All numerical tuning is a survivors adaptation, not a claim to reproduce MMO balance.

## Abilities

Shared: Rifle Shot (existing basic rifle), Overload Shot, Fragmentation Grenade, Flash Bang, Debilitate, Shield Probe, Adrenaline Probe, Escape, Corrosive Dart, Corrosive Grenade, Weakening Blast and Cull.

Operative: starts with Shiv and Corrosive Dart (Rifle Shot is not equipped); adds Backstab, Hidden Strike, Laceration, Stealth, Cloaking Screen, Stim Boost, Kolto Injection, Kolto Probe and Surgical Probe. Knife attacks cleave without talents. Tactical Advantage caps at two, expires after twelve seconds, and is generated once per Shiv/Hidden Strike activation. Laceration spends a charge for bonus damage but remains functional without one. Surgical Probe requires a charge. Kolto Probe heals over eight seconds. Medical talents add generation and conditional refunds. Stealth abilities provide six-second offensive openings; Hidden Strike consumes the opening.

Sniper: starts with Snipe and the slot-free Rifle Shot; adds Ambush, Series of Shots, Followthrough, Suppressive Fire, Orbital Strike, Explosive Probe, Interrogation Probe, Plasma Probe, EMP Discharge, Cover Pulse, Entrench and Ballistic Shield. Precision attacks ricochet without talents. Precision casts enable a six-second Followthrough window. Suppressive Fire channels over a cluster; Orbital Strike delivers three persistent ground ticks. EMP recovers probe cooldowns. Remaining stationary for 0.6 seconds provides 15% damage; movement immediately removes the bonus and never requires a crouch. Entrench provides six seconds of mitigation.

Both classes use the same owned-poison counting implementation for Cull, with class-specific ranges. Two owned poisons grant 70% bonus damage. Existing periodic ownership and refresh rules remain intact. Early offers prioritize offensive coverage; utility unlocks enter the offer pool at level seven.

## Talents

Medicine / Concealment / Lethality and Marksmanship / Engineering / Lethality each expose nine freely selectable, one-rank talents per tree in the same 3×3 layout as other classes with a class-specific ten-point budget. Lethality definitions and mechanics are shared across the two classes; saved profiles remain separate. Other classes retain their existing budgets. Talent effects include medical Advantage generation/refunds, poison application from knife/rifle hits, stronger stationary positioning, extra ricochets, wider cleaves, probe cooldown recovery, longer/faster poisons and Cull execution damage. The UI shows Tactical Advantage/openings or positioning status.

Existing D3 rifle/sniper models, movement and firing animations remain in use.

Recovered: Shiv and Backstab JBA; original shiv and plasma-probe geometry; 156 effect dependencies and 42 converted textures; 103 original audio media with event graphs. Knife impacts and orbital/plasma audio use recovered Agent events. Advanced ability icons come from original `ablIconSpec` values.

Limitations: native SWTOR FX graphs are adapted by the existing bounded Godot presentation system; exact native emitter timing, attachment transforms, Wwise random/switch behavior and visual fidelity are not reproduced. The knife-combo candidate did not uniquely resolve in April, so Laceration reuses original Shiv motion. Hidden Strike reuses Backstab. The fragmentation explosion candidate did not uniquely resolve; its adapter reuses recovered explosive artwork. Probe/medical utilities still reuse some existing Agent gestures and sounds. Stealth is an offensive-opening adaptation, without invisibility or enemy threat reset. Escape clears vulnerability and grants movement assistance; this game has no player crowd-control state to break. Adrenaline Probe restores cooldown readiness because MMO energy is not modeled. EMP recovers cooldowns rather than destroying persistent probes. Engineering probes are area damage/periodic effects rather than native attach-and-trigger bomb entities. Plasma ground visuals are finite approximations of the recovered effect. Talent names/icons without exact individual bindings are adaptations using recovered Agent art; do not treat all selected names as source-confirmed 1.2 talent bindings.

## 3×3 balance refinement

Each class now has 27 choices; ten points and hybrid support remain unchanged. The shared Lethality tree has nine definitions used independently by both class profiles. Existing saved talent IDs retain their meaning. Agent screens now use the established three-column, three-row layout instead of the former two-column positioning.

The additional row adds Medicine poison-based sustain, medical shields and an emergency response; Concealment repeatable offensive openings, multi-ability knife scaling and Advantage sustain; Marksmanship Rifle Shot/Snipe ricochets, follow-up cooldown recovery and mobile shielding; Engineering artillery scaling, probe crowd control, EMP sustain and cooldown recovery; and Lethality poison scaling, bounded poison spread and defensive sustain. Limits follow existing Warrior/Sorcerer examples: 2 HP per second for sustained healing, 8–10 HP proc shields with six-second locks, 10% temporary mitigation, and roughly 15–20% multi-ability training. This is a comparable tuning budget, not proof of identical damage in all builds.

The smoke runner also verifies starting loadouts after restart, the 3×3 grid coordinates, ten-point three-tree hybrids, new sustain caps, shield capacity, temporary mitigation expiry, knife scaling, Rifle Shot ricochets, artillery scaling and actual spread of both owned poisons. Long-run parity across all enemy waves remains a playtesting concern.

## Animation and effects repair

Agent movement now uses recovered forward/backward rifle cycles through the same directional blend and measured foot-stride playback system as the other developed classes. Lateral leg adaptation follows the existing weapon locomotion implementation. Playback reacts to actual movement speed rather than playing a single forward cycle at a fixed rate. The captured baseline rates are approximately 1.35× forward/lateral and 2.05× backward at the standard run speed.

Recovered additional motions: rifle grenade, detonator, full-auto start/loop/end, sniper series, Hidden Strike/waylay, medical healing and rifle locomotion. Hidden Strike no longer reuses Backstab; medical abilities no longer use the shield animation; probes no longer use grenade throws; Orbital Strike no longer uses a sustained rifle firing animation. Candidate availability and original hashes are recorded in `agent-presentation-source.json` and `agent-conversion.json`; final resource bindings are in `agent-presentation-bindings.json`.

The knife is fitted once per activation and follows the full animated LeftWeapon transform throughout the gesture. Persistent poison, interrogation and plasma visuals follow their target and share the periodic record's refresh/death/removal lifecycle. Plasma includes both recovered probe pieces and a correctly sampled 5×5 flame atlas; interrogation uses electricity rather than flames. Medical probes and healing rings, stealth activation, electrical control impacts, explosive probe impacts and an original ballistic-field sphere/hex projection now have distinct adapters. Orbital Strike uses a ground marker and one beam/explosion presentation per tick rather than spawning a beam for every victim. Recovered shot audio now plays throughout Cull and Suppressive Fire. New Agent extraction totals: 193 FX dependency resources, 51 texture conversions and 141 audio media. Shared original dependencies remain in their existing D3/PresentationRepairs manifests.

Validation now includes every available Agent ability's presentation initialization/reset, movement in four directions, finite calibrated stride rates and attached status refresh/removal. Rendered captures are saved as `agent-operative-running.png`, `agent-operative-shiv.png`, `agent-operative-koltoprobe.png` and corresponding Sniper running/orbital captures.

Remaining fidelity gaps: neither knife-combo candidate nor the artillery start/mid/end candidates has a unique April match. Laceration still uses original Shiv motion; artillery uses recovered Detonator as a compatible call-in substitution. Medical motion is an original compatible heal gesture, not a recovered exact ability-to-animation schedule. Untextured effect geometry uses the established metallic material adapter. Ballistic Field uses original sphere/hex artwork with a Godot material, not the native projection shader. Native emitter scheduling, engine zap primitives and exact Wwise switch/random behavior remain adaptations. Stealth activation feedback does not add native invisibility/threat logic. The unique fragmentation explosion candidate and toxic-haze loop remain unresolved; missing candidates are not proof of archive absence.

## Concealment knife attachment and sound correction

The earlier generic LeftWeapon attachment was wrong for the animations currently in use. Recovered `sp_shiv_01`, `sp_backstab_01` and `sp_backstab_knife_only` FX bind the knife to `rightweapon`; the model appears after 0.066 seconds in Shiv. The recovered native Laceration FX uses a different left-hand, rotated/offset attachment, but that native combo animation is unavailable. The current Laceration fallback therefore follows its actual Shiv animation's right-hand socket instead of mixing the left-hand native effect with the right-hand fallback motion.

`AgentKnifeVisual` owns one knife per actor, follows the animated RightWeapon transform, uses a fitted 0.065-world-unit blade, hides the equipped rifle while active, and restores its previous visibility on finish, interruption, replacement or release. The blade now appears throughout the attack, with the source Shiv appearance delay, instead of on the wrong hand or overlapping the rifle. Debilitate no longer draws an unrelated knife.

Shiv, Backstab, Hidden Strike and Laceration now have a recovered electrified knife sound during the swing and a separate contact sound 0.35–0.4 seconds into the strike. Laceration uses its recovered `Play_ability_spy_laceration_impact` event. Other attacks use recovered Backstab contact audio; Shiv's referenced `Play_ability_spy_lethalthrow_impact` had no resolved playable graph in this bank, so Backstab contact is an explicit reuse. Knife cues use -10 dB per-voice gain rather than the generic -18 dB (the player's combat bus settings still apply). The 0.72-second electrical sound is finite and its scheduled stop remains bounded by the gesture. Cleaves play contact audio once per activation rather than restarting it for every victim.

`agent-knife-audio-bindings.json` records event/media identities, duration and measured non-silent RMS. FX/byte provenance remains in `agent-fx-source.json` and `agent-audio.json`. Presentation checks cover right-hand transform alignment, actual rifle hiding, audible-voice playback, one contact event per cleave and effect cleanup. Laceration's missing native combo motion remains a source limitation.

## Automatic Sniper cover

After 0.6 seconds standing still on the ground, Sniper blends into the recovered `cb_rifle_cover_crouch_hide_idle_1` animation and deploys portable cover in front of the character. Movement and jumping immediately release the pose/barrier. Rifle attacks use recovered `cb_rifle_cover_fire_right_1`; probe/ordnance gestures use `cb_rifle_cover_detonator_01`. These are original recovered JBA motions; no character animation keyframes are generated. Normal animation blending supplies the stationary crouch transition; the original far-distance cover-roll entry is recovered but deliberately not played for automatic stationary cover.

Portable cover uses the original `sp_portableshield_device_whole_01.gr2` and `sp_portableshield_field_01.gr2` from `sp_portablecover_dynamiclength_01.fxspec`, with the source 90-degree field attachment rotation. The device's `fx_sp_portableshield_device_main.mat` references `art/fx/geometry/smuggler/texture/fx_devices_01_d.dds`; the field's `fx_sp_portableshield_field.mat` references `art/fx/geometry/spy/texture/fx_portablecover_grid_01.dds`. Both are uniquely recovered April entries with original bytes and hashes in `agent-fx-source.json`. The apparent Smuggler texture folder is the literal original material dependency, not a substituted asset. No new barrier mesh, grid texture or character motion is synthesized. Native Hero materials are adapted to Godot materials using these original textures; the source Uber lighting/projection system is not executed natively. Startup/shutdown cues come from recovered portable-cover Wwise events.

The existing positioning damage bonus and Ballistic Dampers talent now require grounded stationary cover conditions. Cover itself adds no new equipment slot or physical movement obstruction. Reset, jumping, movement and death retract the barrier. HUD status reads “In Cover +15%”. `sniper-cover-smoke.json` verifies timing, native firing selection, barrier placement, movement exit, re-entry, jump exit, restart and death cleanup. The rendered native-asset preview is `manifests/sniper-portable-cover.png`.

### Original edge projectors

The final portable-cover assembly restores the original deployed `sp_portableshield_device_main_01`, `_left_01` and `_right_01` GR2 meshes, plus `sp_portableshield_projection_01` and `_02`. The left/right source anchors are `(0.065,0.11,0)` and `(-0.065,0.11,0)` with `(90,90,0)` and `(90,-90,0)` attachment rotations. The closed `device_whole` model is retained in the archive conversion but is no longer the deployed assembly. All parts share a common source scale, retaining their relative proportions. The original FXSpec identifies two side devices and a central base, not four independently placed corner devices. The projection mesh pair supplies the connecting beam artwork. Exact layout records are saved in `sniper-cover-layout-evidence.json`.

The temporary generic metal/hex material setup has been removed from portable cover. The final device uses the original `fx_devices_01_d` material texture and the field uses its original `fx_portablecover_grid_01` texture with source UVs. Projection meshes use `fx_sp_portableshield_projection_01_d`. No procedural cover geometry, generated grid, replacement character keyframes or invented four-projector layout is used. Godot material and lifecycle adapters remain necessary to display these original assets outside the Hero engine; native particle trajectories and shader execution are not reproduced exactly.

### Cover mapping correction

The initial brightness refinement reduced the mesh grid and beam opacity. This was superseded by the native projector-layer correction below: dimming the grid did not reproduce the original field appearance.

The previous assembly mixed fitted GR2 geometry with literal FXSpec offsets and independently reversed the Z offsets. This separated the projector fans from the curved field. The final assembly keeps the imported meshes in their original shared units, retains source offsets unchanged, applies the original field parent scale `(1.2,1.1,1.1)`, and converts source-facing coordinates once at the common root. Field deployment grows the local height axis of the rotated original mesh rather than scaling its depth.

Projection fans now tilt toward the field instead of remaining upright behind it. The tilt uses the upward/forward `.002/.001` components of the recovered particle trajectory as an adapter for `AlignToTrajectory`; native random lateral trajectory motion is not reproduced. This orientation is a source-informed adapter rather than proof of exact native particle execution. Both original beam meshes and their source texture are retained. No extra cover plane was added: the cover field has one connected mesh surface. `sniper-cover-smoke.json` now checks the single shield surface, shared model units, exact field anchor/scale, single facing conversion and actual beam-tip containment in the shield's local bounds. Front/side captures are saved alongside the main preview.

### Native projector-layer appearance correction

The original FXSpec sets `geo_field` / `geo_field1` diffuse colour to `(0,0,0,0)`. The visible surface is supplied by `proj_portable_cover` / `proj_portable_cover1`: recovered `proj_hexgrid_tile.dds`, tinted `(.442,.614,.958)` at intensity 2, multiplied by recovered `bw_projector_glowbar_blue_shield.dds`, tinted `(.114,.353,.646)` at intensity 1.5–1.8. The earlier square grid was the receiver's base material displayed without these projector layers. The native hex texture is therefore source-confirmed; the earlier removal of all hex materials was too broad.

`SniperCoverField.gdshader` now samples those exact two original textures on the original curved mesh, using source projector centre/size, source 6–5.9 / 5–4.9 tiling endpoints, 1.2 layer-one tiling, MULT layer combination and additive output. It applies no procedural hex pattern, invented replacement texture, synthetic mesh or replacement animation. The original projector records are retained in `sniper-cover-layout-evidence.json`; texture extraction hashes remain in `agent-fx-source.json`. Godot uses a receiver-local planar shader adapter rather than executing Hero's projector: native volume clipping, precise P-curve playback and colour-space equivalence remain unverified. Repeating linear playback is an adapter interpretation of the saved P curves, not native behavior verification.
